Audited every "ok: true" return site across src/services/aiTools/*.ts

FOUND AND FIXED (same shot, in operationalTools.ts):
- manageUsersAndRoles: user_roles.upsert() error was only console.warn'd;
  profiles.update() error wasn't checked at all (no `error` destructured).
  Function always returned ok:true even if the role grant/update silently
  failed. This is an RBAC/permissions tool, so this was a real-consequence
  bug. Fixed: role upsert failure now throws and returns ok:false with the
  real error; profile-field failure is now caught and reported in the
  success message without masking the (successful) role change.
- sendPushNotification: store_settings update result was discarded
  entirely (no destructured error), wrapped in try/catch that only
  console.warn'd. Always claimed "تم بث الإشعار الفوري ... بنجاح" even if
  the DB write failed and even though the tool doesn't send any real push
  notification (no FCM/OneSignal/etc. — it only edits the on-site
  announcement bar). Fixed: now tracks whether the in-memory layout update
  and/or the DB persist actually succeeded, returns ok:false only if
  neither happened, and the success message now says plainly when the
  change is DB-persisted vs. session-only. Left a code comment flagging
  the "push notification" naming mismatch for a product-level decision
  (not fixed here, since renaming affects the AI-facing tool schema).
- manageDeliveryZones: none of the three write paths (update by id, update
  by matched name, insert new zone) checked the returned `error` at all —
  only `data` was destructured. Always returned ok:true regardless of
  whether the write succeeded. Fixed: all three paths now check `error`
  and throw on failure; the whole function is wrapped in try/catch
  returning ok:false with the real Supabase error message.
- exportReportsAndAnalytics: a failed orders/order_items/products query
  was caught and swallowed, then reported as a "successful" report showing
  0 revenue / 0 orders — indistinguishable from a genuinely empty store.
  Fixed: query failures now short-circuit to ok:false with the real error
  instead of being presented as real (zero) data.

All four fixes follow the pre-existing pattern already used correctly in
coreCatalogTools.ts's toolManageProduct (throw on Supabase `error`, wrap in
try/catch, return ok:false with (e as Error).message on failure).
